# 原生工作流节点合同 v2.1.0

交付YAML是精确节点名、NodeCode与接线的配置基准。下列按职责说明合同，不要求维护者照旧v2.0的Group→Profile→编号菜单手工拼图。

## 入口与选择

Start必填 `task_id`、`reported_group_text` 两个字符串。主 Agent 收到体验请求即调用，不在外层重复收集大类或活动偏好。明确的大类原文只取本人当前所属说明；唯一匹配时直接复用，未知或同名歧义才到大类按钮。大类只收集一次。Profile年级/经历节点不再是体验步骤。

活动/情境以按钮展示通俗名称，内部值由分支固定映射。按钮结果用 `optionId` / `optionContent` 及分支承接；不让学生输入编号，不让模型再从按钮文本猜选择。当前导出未证实选项节点的“其他”分支自由输入原文字段，该分支只安全结束并保留记录。需要自然修改时先点“我想改一下”，在直接回答节点输入，才使用本人原文提取或澄清。原生字段细节以实际导出及生成YAML为准。

StartCase固定当前案例、版本和大类，不让检索或模型修改。知识增强版在开题前可解释方法背景与未覆盖内容；知识节点只读真实 `outputList`。空检索正常降级，不补编课程和来源，不阻塞已完成内容的结束报告。

## 方案与计算

当前题面→本人作答→提取候选→校验原话与字段→展示理解→本人明确确认→代码计算。固定选择题可以按钮选择；数值与路线保留输入。模型不计算、不选方案、不改理由。方案中的非空理由必须是本轮连续原话。

确认按钮直连明确确认操作；自然修改先生成新预览，不直接把新值当计算授权。含糊确认不算；求助和澄清不算；Gate同时检查 `ok=true` 与 `action=evaluated` 后才可以进入下一阶段。各分支只接自己真正执行的上游状态，不能用聚合取得旧的失败状态或空值。

Advance继续同一情境。数值题在新条件下复算原方案；选择题只保留当时选项全文、展示新证据后重新选，不把旧字母当新方案。第二阶段题面、选项、提取信息和状态都绑定Advance后的路径。

## 随时结束与记录

所有可回答阶段都提供结束入口，使用当前有效 `state_json` 调用 `finish`。明确的自然语言结束请求优先于普通提取、阶段检查与反思处理；否定、引用、假设和仅提及“结束按钮”不自动退出。按钮分支无需再依赖文本分类。

结束直接生成实际完成部分：已确认方案和结果；必要时包括新条件下原方案复算；提出但未确认的方案单列；未写或未确认反思分别说明。停止不等于异常，不要求先反思或确认报告，也不宣称做满两阶段。重复获取已结束记录不能新开体验或重算。

复盘围绕本题实际事实，可以不确定或跳过。明确的意向专业保留原有数据，修改感受不应清空。记录确认与方案确认分开；只有本人明确确认整份记录后才写已确认。反思自由更正先生成未确认草稿，不暗中完成确认。

## 展示与唯一End

每条正常结束、已确认、未确认及可恢复失败路径生成自己的 `final_text`，互斥终态进入汇聚后连接唯一End。不可把未执行分支空字段当最终正文，也不可只接停止说明而漏掉已有报告。

显示层可以使用运行层 `display_text`，或分时显示题面/预览/反馈/报告，避免重复。标题、段落、粗体和斜体是正文的一部分。原话独立引用并展示转义；后台保留准确原文。内部状态、案例ID、JSON和诊断信息只用于接线与维护。

信息节点保留平台必填参数抽取占位；业务不要误读占位。按钮读按钮输出，直接回答读 `USER_RESPONSE`。代码保持真实导出所用同步入口约定。状态来自可信上游而非模型生成或学生可编辑JSON；格式校验不是状态签名。

所有工作流仍需租户验收：实际按钮、其他分支、Markdown、挂起恢复、超时、真实模型提取、知识召回和账号隔离不能由本地静态检查证明。
