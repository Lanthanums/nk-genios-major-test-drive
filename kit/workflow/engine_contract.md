# 运行层接口合同 v2.1.0

包内 `code/engine_source.py` 是维护源码；`code/engine.py`、`code/platform_runtime.py` 与 `code/hiagent_node.py` 为嵌入题库和目录的运行版本。不要把BANK/CATALOG仍是空占位的源文件直接粘到平台。标准库计算内核不调用模型或网络。平台包装保持既有同步入口；完整内核也保留 `handler(params)` / `async main(params)` 兼容接口。

## 返回字段

统一字段为 `ok`、`action`、`state_json`、`prompt`、`preview`、`feedback`、`result_json`、`report`、`error`，并新增适合完整展示的 `display_text`。原始 `engine.py` 有状态时还返回 `case_id`、`task_id`、`phase`、`title`、`variant_id`、`normalizer_context` 与 `knowledge_query`。平台适配器只导出 YAML 的 OutputSchema 所列字段，另补齐 `mode`、当前 `choiceA/B/C`、`record_summary` 等字符串；不要引用未声明的原始内核字段。目录、范围、复盘等操作按需带额外字段。

`display_text` 包含阶段说明和本次应显示的内容；有报告时只包含一次报告，再附必要核对说明。可以使用它完整显示，也可以分时显示各正文组件，不能两种同时重复。`error` 是诊断字段，不给学生展示；失败时 `feedback` / `display_text` 提供友善恢复说明，输入状态有效时也返回已有报告。

内部 `phase=0/1`、状态码、案例ID和JSON只用于机器传递。学生看到第一次方案、条件变化和实际记录，不需要知道这些内部编号。

## Start与目录

工作流入口接收必填 `task_id`、`reported_group_text`，但内核 `start` 使用已由入口确认/按钮映射的大类ID。二者不能混为同一层。

```json
{"op":"start","task_id":"sensor","case_id":"sensor_luggage","group_id":"physics_opto","group_confirmed":true,"cohort":"未知"}
```

大类不明时用 `unknown/false`，仍可体验，只不判断个人类内范围。不要默认2026级。目录只按用户清单区分类内/跨类/待核验，不等于学校认证身份。`catalog` 返回9类27情境和8组大类供平台映射；内部自动选择和排除列表继续兼容，不直接展示给学生。

## 提取、预览、确认

`propose` 接 `state_json`、`user_text` 和 `candidate_json` 或 `plan_json`。候选只含当前题允许的方案字段，理由和quote绑定本轮原文；不接受模型改写理由或补充答案。返回等待确认时没有计算结果。按钮直接选择的值由分支固定传入，不必再由模型识别编号。

`confirm` 接当前状态与明确确认原文；按钮“按这个方案试一试”可直接确认。路线、阈值、调整力度及A/B/C短句修改先形成新预览；更复杂的自然修改仍应走提取→propose，不承诺单靠内核理解全部自然语句。含糊确认不计算。

`evaluated` 才是计算成功动作，包括方案不可行这一真实结果。数值结果只取 `result_json`；模型不重新估算。选择题反馈是给定条件下的方案反馈，不是能力评分。

## 条件变化与反思

`advance` 仅从第一次已计算状态进入条件变化。数值题复算旧方案，选择题不按旧字母复算。当前阶段选项按事件原阶段解释，报告保留选项全文和方案原话。

`reflect` 保留本人原话，明确“不确定/跳过”可记为跳过，不补写兴趣。`confirm_record` 只在明确确认后把整份记录标为已确认。自然更正反思保持未确认草稿，等待再核对；兼容“更正并确认：…”完整替换反思。专业意向应复用此前明确值，不因仅改反思清空。

## 正常结束

```json
{"op":"finish","state_json":"当前可信上游状态","user_text":"结束并给我报告"}
```

任何有效状态都可结束，返回 `ok=true/action=stopped` 和已有报告；不要求先确认新方案、做满两次、反思或确认整份报告。`stop` 保留兼容。清楚的自然结束请求在普通阶段检查前处理；按钮直接调用finish，不依赖文字解析。

已确认方案保留不变；未确认方案保留在 `unfinished_plan` 并明确未计算；未填写或未确认反思如实说明。重复finish不重复追加事件。已结束后再索取记录安全返回同一记录。`report` 是只读快照操作，不伪造确认。

否定、引用和假设不当退出，例如“我不想结束”“你说的‘结束’是什么意思”“如果结束了会怎样”“看到结束按钮”。解析是保守规则，不保证覆盖所有表达，因此平台也保留明确结束按钮与澄清分支。

## 原话和错误

后台 `raw_text`、`proposal_raw`、`reflection_raw` 保留准确原文；展示时另起引用块、转义Markdown/HTML、不追加标点。多行、句号、星号、方括号与模板文本不能变成报告格式指令。

失败返回操作前有效状态，防止部分修改混入后续；已有报告随返回保留。不要把错误、求助或需要澄清分支送去计算成功路线。没有有效状态时不能虚构旧记录。状态格式校验不是密码签名，学生和模型不能任意提交可信恢复JSON。

数值核心与27个情境规则未改。12项运行层回归、1512次阶段结束重放及9个旧数值快照均为本地代码证据，不代替平台导入、真实模型或挂起恢复测试。
