# 专业试驾场 v2.1.0 实施方案

本轮围绕“学生能看懂、能选择、能随时结束并带走真实记录”升级交互。学科内容仍为9类27个固定情境、65份知识资料和36条中文官方来源记录。模型负责自然语言理解与资料解释；固定题计算和报告事实由代码负责。

## 入口和大类只由一个流程负责

主 Agent 收到体验意图后直接调用 `WF_Explore_One_v2`，传两个必填字符串 `task_id`、`reported_group_text`。没有明确活动时传内部默认值；没有本人已明确的当前大类原文时传空串。Agent不先展开另一份活动菜单，也不在外层询问大类、年级和经历。

入口检查当前聊天中本人明确说明的大类。唯一对应时直接用于本次记录，不再次确认；未知或两个同名班无法区分时，工作流显示一次按钮。意向专业、他人大类、希望转入的大类和任务表现都不能作为当前所属大类。本人说明不是学校核验身份，范围判断仍按项目用户清单进行。

## 按钮负责有限选择，文字负责表达

大类、活动/情境、固定方案、方案确认、继续及结束使用平台原生信息收集选项。按钮的分支直接对应内部值，不让模型再猜学生选了哪个编号。当前选项导出没有证实“其他”分支的原文输出，因此该分支安全返回已有记录，不猜测自由文字。修改先点“我想改一下”，进入直接回答页后才提取自然语言或澄清。

路线、阈值、调整力度、理由和反思保留自然输入。提取候选后展示给本人核对；只有明确确认后才计算。普通修改先展示新方案，不把含糊“可能吧”当确认。按钮内容与当阶段题面一致，避免用同一个字母误读前后不同方案。

## 体验与结束

题目前说明：先试一个方案，看看条件变化后会怎样，最后可留下感受；任何时候都可以结束并查看已有记录。只做一次也可拿报告，不用补答后面的题。每个可回答节点都有正常结束分支，自然结束句也优先识别。

数值题在改变条件后复算原方案，选择题则展示新条件及原选择全文、重新选择，不用旧字母计算新选项。控制题同时展示初始位置、目标、观察步数、每步限幅、外部影响与更新规则，避免学生看不到规则却被要求选参数。

提前结束保留实际试算事实。未确认方案单列且不计算；未填写反思不补写；方案已确认不代表本人确认了整份报告。反思可跳过，修改反思不应清空此前明确的专业兴趣。重复索取同一已结束记录不重算、不重启流程。

## 展示和原文

学生看到的长文本使用Markdown标题、段落、粗体重点和斜体注释。必要的专业术语用一句话解释；后台JSON、内部默认值、案例编号和状态码不进入学生指令。引用本人原话另起引用块，保留原标点，展示时转义Markdown/HTML，存储时保留准确原文。

## 知识库和专业范围

专业知识问答无需先取得所属大类。解释个人可选范围时复用本人已说明的大类；缺少时说明限制或只问一次。知识库只支撑学科方法和学习背景，不更改在途题目规则、不替代清单成员关系检查。

本轮保留专业知识事实和来源核验日期，只更新 `00_scope.md`、`05_faq.md` 交互说明。完整v2.0知识库已索引者替换这两张卡，其余63份无需重传；仍使用更旧资料者需要更新完整65份卡片。开放练习仍为待审核草稿，结构和引文校验不构成学科审核，不进入固定题库。

## 验证与交付

原三任务的9个数值快照保持一致。当前运行层回归检查包含1512次提前结束调用、原话排版、否定/引用退出反例、重复结束、错误恢复、反思修改与控制题规则完整性。新增两份完整模拟案例由代码重放产生计算事实。

主工作流保留单End，用互斥终态汇聚。新主 Agent 提示词、两个入口字段、按钮分支、运行层和文档应作为同一版本更新。平台验收单独检查按钮渲染、自然输入“其他”分支、Markdown、暂停续答、检索和模型提取，不能用本地重放冒充线上验证。
