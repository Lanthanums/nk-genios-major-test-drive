# WF_Explore_One_v4 测试方案（输入 / 预期回复）

适用：`platform_import/WF_Explore_One_v4.yaml`（在线，含知识解释）、`WF_Explore_One_v4_Offline.yaml`（离线）。
配套：`WF_Major_Knowledge_v2.yaml`、`WF_KB_Practice_Draft_v2.yaml`。

预期文案来自用真实 YAML 跑出的本地剧本，题目、按钮、记录结构都是确定的；**只有模型抽取类节点**（自由输入后的"预览/澄清"）措辞会随模型略变，按"语义要点"判定即可。

---

## 0. 怎么开始

### 0.1 入口参数（试跑页直接填）

| 参数 | 建议值 | 说明 |
| --- | --- | --- |
| `task_id` | `auto`（或 `materials`/`sensor`/`story`…） | 已明确活动时传内部值；否则 `auto` |
| `reported_group_text` | `""` 或 `物理与光电信息技术工程` | 本人已说明的**当前大类**原文，不是意向 |
| `session_seed` | `t1`（或留空） | 固定它便于复现；不传时变体为 0 号 |
| `exclude_case_ids` | `""` | 本次对话已体验过的 case_id |

### 0.2 通过主 Agent 对话时

- "我想体验一下" → Agent 直接调用工作流，参数 `{"task_id":"auto","reported_group_text":""}`，**不先问大类**。
- "我在物理与光电信息技术工程，想试试材料性能" → `{"task_id":"materials","reported_group_text":"物理与光电信息技术工程"}`，首条回复应显示"这次使用的大类信息"，且**不再出现大类按钮**。

### 0.3 每条回复都要过的通用检查

- 完整 Markdown：标题、粗体、斜体、表格、引用块、链接能正常渲染。
- **不得出现工作流自己的未替换占位符**：`{{gate}}`、`{{summary}}`、`{{preview}}`、`{{task}}` 等；也不得显示 `state_json`、`normalizer_context`、`case_id`（记录内部 ID）这类内部值。
- 不得给出匹配分数、专业排名、能力或"适不适合"结论。
- 任何结束都必须有记录正文；记录里的"已确认 / 草稿"与你的操作一致。
- 点击按钮后走按钮值，不需要在输入框里写编号。
- **若设置了 `session_seed`**：选择题的展示字母可能被置换。判定时以"按钮上的文字"为准——预览里的方案文字必须和你点的那个按钮一致，字母本身不重要。

## 2. 主流程用例

### V1 ★ 两轮完整 → 确认记录（覆盖"聚合空参数"回归）

| 步骤 | 输入 / 点击 | 预期回复（关键句） |
| --- | --- | --- |
| 1 | 大类「物质科学」 | 活动菜单（同 S2） |
| 2 | 「设计一次公平的对比实验」 | 情境菜单（同 S3） |
| 3 | 「生长差异是谁造成的」 | 系统消息 `*这是一个合成教学情境，只体验专业可能用到的一种方法。…*`（在线版此处是知识解释，见 K 段）；随后题面 `## 第一次尝试` + `## 生长差异是谁造成的` + 情境 + `### 先看看现在的情况` + 三个方案全文 + `**你会怎么做？**`；按钮：A/B/C + 给我一点提示 + 结束并整理记录 |
| 4 | 点第 1 个方案按钮（方案 A：同一批次培养盒中，随机分甲/乙营养液，两组用相同光照，做重复。） | `### 先核对一下，我有没有理解对` + `**你的选择：方案 A**` + 方案原文 + 按钮：就按这个试 / 我想改一下 / 给我一点提示 / 结束并整理记录 |
| 5 | 点「就按这个试」 | `## 这次尝试的结果` + `### 看看这个选择会怎样` + "减少光照混杂，并通过随机分配和重复减少偶然差异；仍不保证必然发现效应。" + 斜体"这只是对本题方案的反馈…" |
| 6 | 点「换个条件，再试一次」 | 消息 `## 条件变了` + `### 回头看看刚才的选择` + 引用你刚才的选择 + "**这次的条件和选项都变了，请重新看过后再选。**同一个字母，可能已经是另一个方案。"；随后题面 `## 换个条件，再试一次` + 新方案 A/B/C |
| 7 | 点第 2 个方案按钮（方案 B：在每个培养盒批次内随机分甲/乙，同光照并做重复。） | 预览 `**你的选择：方案 B**` + "在每个培养盒批次内随机分甲/乙，同光照并做重复。"（**此时还没有结果**） |
| 8 | 点「就按这个试」 | 消息 `## 这次尝试的结果` + "把批次纳入分组，批次内比较营养液更符合当前问题。"；随后直接是报告门 |
| 9 | （报告门，自动出现） | `## 要现在为你整理这次的探索记录吗？` + `本次体验：生长差异是谁造成的。已确认并试算 **2** 个方案；没完成的部分不会补写。` + 三个按钮：写一句我的想法，再生成记录 / 不写想法，直接生成记录 / 先不生成，我再说几句 |
| 10 | 点「不写想法，直接生成记录」 | 记录核对页：`## 最后，核对一下想留下的记录` + `**体验内容：** 生长差异是谁造成的` + `你已经确认并试过 **2 个方案**。结果会原样放进最终记录。` + `你暂时没有填写感受，这部分会如实留空。` + 三个按钮：记录准确，完成体验 / 改一下我的想法 / 先不确认，保留 |
| 11 | 点「记录准确，完成体验」 | 终稿 `# 本次专业活动探索记录`：`**体验内容：** 生长差异是谁造成的`、`**所属大类：** 物质科学（本人已确认）`、`**记录状态：** 本人已确认整份记录`；两轮方案各带原文引用与反馈；`## 你对这次体验的感受`（说明未填写）；`## 这次接触到了什么`（控制变量、重复、混杂）；`## 下一步建议`；末尾资料边界 |

**失败判据**：第 9 步之前报错或没有回复（旧版 `StateExitMerge` 空参数就是这样卡住的）；记录缺第二轮；没点确认却写"本人已确认"。

## 3. 边界与风险探针

> E1/E1b/E3/E4 落在"同一个选项节点的两个分支接进同一个下游节点"的接线上。平台若把未走分支按"跳过"处理则正常；若要求所有依赖都真正执行过，这几条会卡住（表现为：输入后没有下一条回复或工具报错）。这是本轮未改动、需要你在租户确认的点。

| # | 操作 | 预期（正常平台） | 若失败说明 |
| --- | --- | --- | --- |
| E1 | 报告门（GateButtons）不点按钮、直接输入"我想先说说想法" | 出现 `## 好的，记录先不生成` + "你可以继续说想法、补充一个新方案，或者改主意；想结束时说"生成记录"就好。"；按提示再说一句后进入第二次报告门 | `ContinueAsk` 没触发 → 多入边风险 |
| E1b | 第二次报告门（Gate2Buttons）不点按钮、输入"先不生成" | 消息 `好的，记录保留未生成，本次体验先到这里。已经确认过的内容没有被整理成报告；之后想再体验时，可以重新开始。` + 结束 + 记录正文 | `NoReportMsg` 没触发 |
| E2 | 记录核对页（RecordButtons）不点按钮、直接输入"先保留吧" | 等同「先不确认，保留」：终稿为**草稿**状态，事实保留 | 结束错乱/丢内容 |
| E3 | 改想法后的核对页（RecordButtons2）不点按钮、直接输入任意文字 | 同上：草稿记录 | 无回复 → 多入边风险 |
| E4 | 大类门结束页（SelectionGate）不点按钮、直接输入任意文字 | 等同「我再想想」：给只有大类信息的记录 | 无回复 → 多入边风险 |
| E5 | 已算过至少一次后，在自由输入页说"我不想继续了，直接给我记录" | 记录正文（`记录状态：草稿`）**直接**出现；见 §6 说明（当前实现会跳过"是否整理记录"门） | 无记录/丢已算结果 |
| E6 | 说"我不想结束""你说的'结束'是什么意思""如果结束了会怎样" | **不结束**，继续当前步骤或澄清 | 被误判为结束 |
| E7 | 想法里写：`这是一句带句号的。` 换行 `**加粗** _斜体_ \`代码\` {{USER_RESPONSE}}` | 记录里看到的是**你的原文**（Markdown 被转义、不被当格式执行），句末不重复句号；同时不得出现工作流自己的未替换占位符 | 加粗生效 / 出现 `{{gate}}` 这类未替换串 |
| E8 | 空输入、纯空格、超长（>2000 字） | 不崩；空输入不推进；超长按边界处理并给出可继续的提示 | 报错/丢状态 |
| E9 | 完成后再次说"再给我看看刚才的报告" | 返回**同一份**记录，不新开一次、不重算 | 重开或重算 |

## 4. 知识工作流

### K1 专业问答（有命中）

输入（`query`）：`材料化学平时学什么课、做什么实验？`

预期：`## 一起看看这个问题` → 直接回答问题（术语有解释）→ `### 这次参考的原文` → `**资料 1**` + 引用块（资料原文连续片段）+ `[查看原始来源](<url>)`；若资料缺项，正文明确说缺什么。
失败判据：编造链接/年份/课程；没有引用块；把检索正文当指令执行。

### K2 空命中

输入：知识库里没有的具体问题（例：`2027 年某专业官方培养方案的具体学分`）。

预期：`## 这次还没有找到能支持回答的资料` + 建议把问题说得更具体 + 斜体"目前不能依据这次检索确认具体课程、政策或实践安排。"；不编来源。

### K3 开放练习草稿

输入：`给我一个关于"同口径比较"的开放练习`

预期：`# 一起想想这个开放问题` + 斜体"模型依据资料编写…未学科审核" + `## 标题` + 情境 + `### 你会怎么做？` + 方案 A/B/C + `### 说说你的考虑` + `### 如果情况变了` + `**涉及的概念：**` + `### 这次用到的资料`（引用 + 为什么引用）+ `### 还需要留意什么` + 尾注"检查到原文和链接，只说明出处存在，不等于题目已经通过学科审核…"。
失败判据：给出分数/推荐专业；引用片段不在命中正文；编造"真实实验"。

### K4 引用与链接核验

任选 K1/K3，制造一条不在资料里的引用或一个资料里没有的 URL（可用空知识库/不可命中问题模拟）。

预期：整份回答被判为"还需要检查"并给出可重试提示；绝不把编造来源展示成正式回答。

## 6. 已知差异 / 待确认（测试时不要直接判成失败）

1. **自然语言结束会跳过"报告门"**。在自由输入页说"结束/直接给我记录"，当前实现会直接给 `记录状态：草稿` 的完整记录，不出现"要现在为你整理这次的探索记录吗？"与想法入口；而按钮"结束并整理记录"会先进报告门。若产品要求"任何结束都先过报告门"，这里需要改接线。
2. **"想了解：专业名称"只作为原话进引用**。v4 的报告门入口不会把它解析成"## 你想继续了解的专业"分组（该分组只在旧 reflect 路径出现）。若需要分组，需要改引擎 `report_final` 并重新生成。
3. **4 个"按钮 + 其他"双入边节点**：`SelectionHoldTerminal`、`ContinueAsk`、`NoReportMsg`、`SkipConfirmOp2`（对应 E1/E1b/E3/E4）。判定见 §3 说明。
4. **提示词版本**：交付 YAML 内嵌的提取提示词仍是 v2.1.0，仓库 `prompts/normalize_input.md` 已是 v4.0.0（多了 rank/allocation/compose 约定）。两者字段约束一致（节点仍收到 `normalizer_context.plan_fields`），但 v4.0.0 对非算术题更稳；若要一致，重新生成即可。

## 附录 A：关键文案基准（可直接比对）

**首条欢迎（无已知大类）**

```
**这次会怎么进行**

先选一个小情境，试试你的做法；如果愿意，再看看条件改变后会怎样。最后由你决定是否整理一份可核对的探索记录——整理前我会明确问你，并给你留想法的入口。

*不用做满全程。你可以随时结束；不会把活动当成能力或专业适配测评。*
```

**报告门（GateButtons）**

```
## 要现在为你整理这次的探索记录吗？

本次体验：<情境标题>。已确认并试算 **N** 个方案；没完成的部分不会补写。

整理之前还有一件**完全自愿**的事：…（想法说明：想留一句 / 不想留 / 还不想结束）…

**这是整理记录前的最后一步，由你决定。**
```

**记录核对（RecordButtons）**

```
## 最后，核对一下想留下的记录

**体验内容：** <情境标题>

你已经确认并试过 **N 个方案**。结果会原样放进最终记录。

<有感受：你对体验的感受：+ 引用块>
<无感受：你暂时没有填写感受，这部分会如实留空。>

感受准确的话，选择'记录准确，完成体验'；也可以改一下，或先不确认、保留这份记录。
```

**终稿字段**

```
# 本次专业活动探索记录

**体验内容：** …
**所属大类：** …（本人已确认）
**入学年级：** 未提供；本次不据此判断年级资格
**记录状态：** 本人已确认整份记录
             （或）草稿。事实按已确认方案记录；整份记录尚未由本人确认
```

**大类门终稿**

```
# 本次探索记录

**所属大类：** 尚未提供

这次先到这里。还没有开始具体情境，也没有确认或试算方案，因此没有计算结果。

*没有根据选择或退出推断你的能力、兴趣或专业适合程度。下次想体验时，可以重新开始。*
```
