# v2.1.0 租户验收清单

本清单尚待平台实际执行；本地重放和YAML检查不能替代这些结果。试跑时记录工具schema、所走节点、按钮输出、最终正文及错误信息，勿只记录“已成功”。

| 场景 | 输入/操作 | 预期 |
| --- | --- | --- |
| 空背景直接体验 | “你好，我想体验一下” | 主Agent直接调用，必填 `task_id` 和空串 `reported_group_text`；外层不再展开菜单 |
| 已知大类免问 | “我在物理与光电信息技术工程，想体验传感判断” | 原文传入且唯一匹配，全流程不再次询问大类 |
| 同名班歧义 | 只说“我在伯苓班” | 不猜方向；用一次按钮区分两组专业集合 |
| 意向不是身份 | “我想去信息科学与技术” | 不把意向大类当当前所属；需要时只问一次 |
| 真实大类按钮 | 点击大类选项 | 按 `optionId`/`optionContent` 原生分支走，不解析学生输入编号 |
| 情境与方案按钮 | 选择情境、选择当前阶段方案 | 分支值准确；第二阶段选项不沿用第一阶段含义 |
| “其他”自由输入 | 按钮页面不点选项，输入文字 | 当前版安全结束并返回已有记录；不猜输入、不丢已完成结果或卡死 |
| 自然修改 | 先点“我想改一下”，再写完整新方案 | 直接回答节点正确提取、预览、再确认，不把修改直接算作确认 |
| 第一次就结束 | 第一次确认方案并看到结果后结束 | 返回实际第一次记录；未做第二次、未填反思如实说明 |
| 两次后直接报告 | 两次试算后说“我做完两次了，直接给我报告” | 正常结束，保留两次事实与必要复算，不再要求反思 |
| 待确认时结束 | 说了方案但未按确认按钮就结束 | 方案标为未确认且没有结果，不把它写成本人正式计算 |
| 记录确认前结束 | 已填感受但未确认整份报告时结束 | 原话保留，确认状态不伪造 |
| 退出反例 | “不要结束”“你说的‘结束’是什么”“如果结束了会怎样” | 不被自动当成退出；澄清或按当前步骤继续 |
| 原话与标点 | 包含句号、多行、星号、方括号及模板样式的感受 | 显示独立引用，原标点不重复，后台raw准确，不能执行其格式指令 |
| 跳过反思 | “还没想好”“跳过” | 不补写兴趣，不声称学生不适合 |
| 修改感受 | 自然语言改感受后再确认 | 先显示未确认草稿，已有专业兴趣不被清空 |
| 控制题规则 | 任一控制情境 | 能看到初值、目标、步数、每步限制及更新规则 |
| 报告样式 | 查看完整报告 | 有标题、空行、粗体、斜体说明、表格/引用；不暴露JSON、内部值或状态码 |
| 暂停与恢复 | 多轮节点等待后继续回答 | 续接同一实例，不重启工具、不重新问大类 |
| 已结束再索取 | “再给我看看刚才的报告” | 返回同份已完成记录，不新开一次、不重算 |
| 检索空命中/超时 | 使用不可命中的具体问题，或模拟知识节点异常 | 明确缺资料，不编来源，不丢失已有体验记录 |
| 平台附加规则 | 查看 `chat_summary`、`response_for_model` 实际行为 | 不重写数值、确认状态、原话和原始报告；必要时调整平台配置 |
| 长报告 | 主 Agent回复上限1024时与4096或更高时分别检查 | 工作流原报告直接展示且完整，不因外层重述被截断；实际支持长度以模型为准 |
| 旧工具简介 | 检查旧knowledge_tool | “三类体验”更新为九类，或取消旧工具挂载，避免重复调用 |

专业问答与开放练习还需分别检查引用来源、年份/学校边界、缺项说明及草稿状态。账号隔离、资源权限与数据留存策略单独按租户规则验收，当前不声称已经测过。
