## 原话、变量和格式要求

1. 不在变量后面补 `。`、引号或其他句法包装。使用“你刚才的想法”标签，空一行后引用块，引用完再空一行写后续文字。
2. 对学生输入使用一次性插值：不得把插入后的用户原文再次作为模板解释。静态模板应检查变量定义与实际引用一致，但用户原文恰好含 `{{USER_RESPONSE}}` 时不能当成未绑定模板报错。
3. 引用块逐行加 `> `，并对用户原文中的 HTML 与 Markdown 控制字符做展示层转义；原始文字另存在 state 原文字段中。保留换行和标点，不在存储层改写原话。否则学生的 `# 标题`、`**我已确认**`、HTML 等可能改变整份报告外观，造成“系统结论”的错觉。
4. 用 `## 第一次尝试`、`**本次结果**`、`*这是合成数据，只说明本题情况。*` 等固定结构；长表用 Markdown 表，样本一行一个或按实际表格显示。
5. 无效输入提示只问一个具体问题；不同时显示三种活动格式，不要求用户理解“候选 JSON”“state”“校验结构”。

## 大类与范围

- 大类只用于解释可选范围，不能从兴趣反推；未知也可以完成活动和阅读知识。
- 学生本人已明确说明的大类原文唯一匹配时直接复用，报告标明“本人说明”；不得再次问“对吗”。不能匹配、两个同名班仅有名称或没有信息时，显示一次大类选择按钮。复用本人说明不等于核验学校身份或个人资格。
- 大类名称改错时须保留已经做过的活动，不重置报告；知识库问答不要求先提供大类。
- “类内”必须写清是用户提供清单的分类，未核验年级适用性；“跨类”不能表达成绝对不能学或不能辅修。
- 两个同名伯芩/伯苓班用专业集合区分，普通专业和特色班保留全称。此版本不能擅自修改清单来扩大个人资格。

## 额外注意

- auto 的当前自动选题会按 group_id 的 GROUP_FAMILIES 过滤，且同种背景 seed 可总选同一题；应明确只是帮忙安排一次活动，允许学生改选，不能暗示根据大类诊断最适合方向。
- 引导词强调“理由”而系统不评价理由质量。保留这一点，不能因选对三选一称赞学科天赋，也不能因求助推断低兴趣。
- 平台调试 system 末尾被附加了服从 `response_for_model` 和复杂问题调用 `chat_summary` 的规则；这些不是磁盘版主提示词中的内容。必须检查平台级设置，避免工具内容注入指令，避免 chat_summary 重写已核算报告。
- 用户展示的 `knowledge_tool` 描述仍说“三类体验”，但已有九类；发布时同步知识库工具简介，避免 Agent 被旧描述误导。

## 一条学生路径的逐回合期望

下面是行为验收例，不冒充已上线实测，也不预设按钮 YAML 字段。

1. 学生：“我是物理与光电信息技术工程的，想体验一下。”Agent 直接调用体验入口，传原文大类，不先问方向。
2. 工作流：“我们先尝试一个小问题，再看看条件变化后你会怎么调整，最后给你一份记录。中途随时可以点‘结束并看记录’。”直接使用本人已说且唯一匹配的大类，不追加年级、经历或确认问题。
3. 工作流显示通俗体验菜单，例如“看看设备怎样减少误报”“排查一个系统为什么出错”，附一行场景说明。学生选择传感情境。若开始时未说大类，则在这之前只显示一次大类按钮；已明确说过则整个体验不再问大类。
4. 工作流用标题、样本表、错误代价和一句提问展示本题；学生：“先用40，我不想漏掉行李。”
5. 工作流显示结构化确认卡：“**准备使用的阈值：40**”；学生原话独立引用。按钮：就按这个试／我想修改／给一点提示／结束并看记录。
6. 学生点“就按这个试”，系统展示真实代码结果：误报2、漏报0，总代价2。按钮：换个条件再试／到这里，生成记录。
7. 学生继续。工作流解释误报代价改为5、漏报代价改为1，并显示原方案总代价10；学生给65并确认，结果误报0、漏报3、总代价3。
8. 学生：“不继续了，直接给我报告吧。”工作流保留两次结果，跳过反思，直接返回记录，写“本人感受：本次未填写”；不能把结束句当作感受，也不能要求补完反思才能拿到记录。
9. Agent 不补问大类，不再调用体验；可在完整报告后用一句话告知能继续了解专业，但不追加新问题或替用户确认感受。
