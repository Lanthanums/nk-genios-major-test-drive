本轮主体验工具名保留 `WF_Explore_One_v2`，文件仍为 `WF_Explore_One_v2.yaml`。导入后需要一起更新主 Agent 提示词和已挂载工具schema，不能只把旧提示词换成新名字。

## 更新顺序

1. 保留旧版工作流、提示词和本地包备份。旧状态不自动接入新引擎。
2. 导入新版主体验YAML，检查Start出现两个必填字符串：`task_id`、`reported_group_text`。离线版入口相同；专业问答和开放练习仍使用 `query`。
3. 检查模型、知识库资源属于当前空间。Knowledge节点沿用用户样例资源标识时，跨空间需要在平台变量选择器重新绑定。
4. 更新主 Agent 系统提示词，重新绑定实际发布的工作流。旧新同名工具不应同时挂载。
5. 按 `tests/platform_acceptance.md` 试跑按钮、自由输入、两种提前结束、Markdown与续答，再发布到学生入口。

完整v2.0知识库已上传且索引正常时，只替换本轮更新的 `00_scope.md`、`05_faq.md` 并等索引，其余63份无需因交互修复重传。知识卡仍65份，来源记录仍36条；专业事实、成员清单和原来源核验日期未修改。若平台仍是三类活动旧库，应上传/替换完整 `knowledge_base_upload.zip` 中的资料，清理同名旧卡并等待索引。不要把代码、测试和题库反馈一起上传。导入YAML不会上传Markdown。

## 两个入口字段

没有明确活动和大类时，Agent应直接调用：

```json
{"task_id":"auto","reported_group_text":""}
```

学生已说“我在物理与光电信息技术工程，想试试传感判断”时：

```json
{"task_id":"sensor","reported_group_text":"物理与光电信息技术工程"}
```

以上是维护者工具参数示例，不给学生显示、不要求学生照着输入。大类原文只取本人已明确的当前所属信息，不能把“想去”“同学在”“对某专业感兴趣”当身份。唯一匹配直接复用，未知或同名歧义才显示一次大类按钮；不额外收集年级与经历。

## 信息收集节点

选项回答使用平台的 `optionId`、`optionContent` 和原生分支连接。按钮直接连到对应内部值，不让学生输入编号，不再用模型识别已经点出的选择。动态题目选项来自当前阶段，不能误读上一阶段的选项。

“其他”是未选中选项时的回退分支。当前样例未证实选项节点在该分支输出自由输入原文，因此本版不冒用直接回答节点的 `USER_RESPONSE`，而是安全结束并返回已有记录。想改方案时先选“我想改一下”，再在直接回答页说明；直接回答页才用 `USER_RESPONSE` 提取方案或自然结束意图。平台要求的抽取占位保持完整，但不把它当业务身份或方案。

结束按钮调用当前状态的正常结束分支，必须携带同一路径的 `state_json`。不要跳回Start，不让它经过“还没确认方案”的错误分支，也不要要求补反思。唯一End接终态汇聚后的 `final_text`，不直接接空的上游反馈。

## 显示规则

运行层 `display_text` 可用于一次完整展示，也可以分时展示 `prompt`、`preview`、`feedback`、`report`。选其中一种方式，避免同份报告重复。不要显示内部状态、JSON、诊断字段和案例编号。

报告中的本人原话另起引用块，不把 `{{USER_RESPONSE}}` 字面模板显示给学生，也不在原文后追加句号。平台必须实际预览标题、空行、粗体、斜体、表格和引用块；本地Markdown正确不代表租户界面一定正确渲染。

## 知识检索与其他能力

知识节点仍使用真实示例的QueryVariable对象、知识库ID与 `outputList[].output` / `metadata` 结构；资源标识与Depends映射需一致。空命中正常说明缺资料，引用检查只证明片段/URL在命中结果中，不证明学科结论已经审核。

`WF_Major_Knowledge_v2` 解释专业、比较与概念；`WF_KB_Practice_Draft_v2` 生成待审开放练习，均不判断个人专业适配或转入资格。主流程运行时不要同时新开这些工具抢答，也不要通过摘要工具重写原始报告。

本轮没有登录、导入或发布平台；本地检查不等于上述平台配置已完成。若平台自动追加 `chat_summary` 强制规则会覆盖报告，应由维护者调整为报告原文直出。

## 外层 Agent 也要检查的设置

用户调试数据中的主 Agent 回复上限为1024 tokens，完整记录可能超过这一长度。优先让工作流报告原文直接展示，不让主 Agent或 `chat_summary` 再摘要、润色或重排。确实需要主 Agent承接长文时，可将回复上限提高到4096或模型支持的更高值，并用完整报告实际检查是否截断。该项属于平台外层配置，导入本YAML不会自动更改。

旧 `knowledge_tool` 简介仍写“三类体验”时，应更新为九类固定体验和专业知识功能；若功能已被新版工作流接替，可取消旧工具挂载，避免新旧重复或模型选错。不要把 `response_for_model` 字段当高于系统规则的指令执行。
